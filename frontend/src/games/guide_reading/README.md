# 노래방 따라 읽기 (`game = guide_reading`)

말속도 영역 게임이다. 안내 커서가 목표 속도로 문장 글자 위를 지나가고, 사용자는 그 빠르기에 맞춰 같은 박자로 읽는다. 사용자가 읽은 곳은 아래 점으로 따로 보여 준다. 숫자는 모두 초기값이다.

## 라운드

- 라운드 하나 = 문장 5개(`sentences.ts`, 10개를 5개씩 돌아가며)
- 문장마다: 시작 → 1초 준비(잡음 바닥) → 안내 커서 → 끝 → 판정
- 문장을 끝내는 조건(`endRule.ts`). 문장 중간에 숨 쉬느라 쉬어도 녹음이 잘리지 않게 하려는 것이다
  - 실시간 추정이 N(정답 음절 수)의 80% 이상이면: 1초 조용할 때 끝낸다(안내 커서와 관계없음)
  - 80% 미만이면: 안내 커서가 끝난 뒤 3초 조용할 때 끝낸다. 커서가 끝나기 전에는 조용해도 끝내지 않는다
  - 최대 시간: 준비 1초 + 커서 시간 × 2.5 + 4초
- 라운드 성공률 = 통과 ÷ 읽은 문장 × 100. 80% 이상 `up`, 40% 이하 `down`, 그 사이 `hold`

## 판정

- 말속도(음절/초) = N(정답 음절 수) ÷ T_speech(휴지를 뺀 발화 시간, 초). 서버 조음속도(`articulation_rate`)와 같은 정의이고, 검출 음절 수는 쓰지 않는다.
  - 발화는 측정 블록과 같은 대역(60 Hz~8 kHz) 음량이 잡음 바닥 + 10 dB를 넘는 프레임이다. 0.25초보다 짧은 공백은 발화에 넣고, 0.25초 이상은 휴지로 뺀다.
- 변동계수 = σ(음절 간격의 표준편차) ÷ μ(음절 간격의 평균). 간격은 이웃 음절 핵 사이 시간이고, 휴지(0.25초 이상)를 건너는 간격은 뺀다. 간격이 2개보다 적으면 구하지 못한다.
- 통과 = 말속도가 목표 구간 안 + 변동계수가 기준 이하
  - 변동계수를 구하지 못하면(음절 핵이 모자람) 말속도로만 판정해, 구간 안이면 통과다. 결과에는 `cv: null`, `rhythm_checked: false`를 남긴다. 검출기가 못 찾은 것을 사용자 실패로 세지 않기 위해서다.

| 단계 | 목표 구간 | 변동계수 기준 |
|---|---|---|
| 1 | 기준 말속도 ± 30% | 0.60 이하 |
| 2 | ± 25% | 0.55 이하 |
| 3 | ± 20% | 0.50 이하 |
| 4 | ± 15% | 0.45 이하 |
| 5 | ± 12% | 0.40 이하 |

안내 커서 속도는 기준 말속도다.

## 기준 말속도

- 처음: 측정 블록 기준값(`baselines.articulationRateSps`, s1 낭독의 기기 조음속도)이 있으면 그 값, 없으면 4.0음절/초
- 회차마다(라운드 시작 때 진전도를 읽음): 진전도의 `articulation_rate` 판정은 "다시 잡을지"만 정한다.
  - `increase`·`decrease`면 그날 측정 블록의 기기 조음속도로 다시 잡는다. 서버 값을 쓰지 않는 것은 게임 안 말속도를 기기 방식으로 재기 때문이다(실제 녹음 하나에서 기기 값이 서버보다 11% 낮았다: 6.58 대 7.37).
  - 그날 기기 조음속도가 없으면(null) 저장된 값을 유지한다.
  - `no_change`·`pending_mdc`(그 밖)면 유지한다. 진전도를 3초 안에 받지 못해도 유지한다.
- 지금은 최소 측정 가능 변화량이 없어 판정이 늘 `pending_mdc`이므로 기준 말속도가 첫 회차 값에 머문다. 최소 측정 가능 변화량이 채워지면 움직이기 시작한다.
- 사용자별로 기기에 저장한다(`games/guide_reading.json`, 키는 `GameProps.userKey`). 범위는 1.5~9음절/초

## 음절 핵 검출 (진행 표시와 변동계수용)

- metrics-spec.md 5장 기기 권장 방법:
  - 50 ms 이동평균 음량 곡선의 정점을 찾고, 정점에서 2 dB 넘게 내려가면 확정한다.
  - 정점 사이는 최소 0.12초다.
  - 정점은 잡음 바닥 + 10 dB 위이고, 유성 프레임(pitchy 명료도 0.85 이상) 근처여야 한다.
- 대역: 말소리 대역 300~2500 Hz 음량. 실제 녹음 하나(s1, 21음절, 빠른 낭독 약 6.6음절/초)에서 비교한 결과다.

| 대역 | 찾은 음절 수 |
|---|---|
| 60 Hz~8 kHz | 13 |
| 300~2500 Hz | 14 |
| 500~2000 Hz | 13 |
| 800~3000 Hz | 12~13 |

- 놓치는 주된 이유는 유성 프레임 조건이다(빠른 낭독에서 명료도 0.85 이상인 발화 프레임이 49%). 녹음 하나에 맞춰 매개변수를 조이지 않고, 아래 보정으로 진행 표시를 채운다.
- 진행 표시 추정(`live.ts`):
  - a(검출 기반) = 검출한 음절 핵 수 ÷ r(사용자별 검출 비율)
  - b(시간 기반) = 발화 시간(초) × R(기준 말속도)
  - 추정 = max(이전 추정, 0.7 × a + 0.3 × b)
  - 문장을 끝내기 전에는 N − 0.5를 넘지 않고, 줄지 않는다
- 검출 비율 r: 처음 0.7. 문장마다 r = 0.7 × 이전 r + 0.3 × (검출 ÷ 정답)으로 고치고, 0.3~1.2 안에 둔다.
- 실제 녹음 시험: 환경 변수 `DYSPEECH_REAL_DIR`(그 폴더에 `eval_sentence_s1.wav`, `noise_floor.wav`)가 있을 때만 돈다. 녹음은 저장소에 없다. 예: `DYSPEECH_REAL_DIR=/녹음/폴더 npm test`
  - 검출 14/21, 말속도 6.58음절/초(서버 조음속도 7.37, 기기는 발화를 음량으로만 나눠 발화 시간이 길게 잡힘), 변동계수 0.23
  - 실시간 추정은 끝에서 19.3/21이었고, 말하는 동안 추정이 가장 오래 멈춘 시간은 0.02초

## 라운드 기록 (`game_runs`, api.md 7.2)

- `params`: `sentence_ids`, `target_rate_range`[아래, 위](음절/초), `guide_rate`, `cv_max`, `reference_rate`, `reference_source`(`baseline` / `default` / `stored` / `rebaseline`)
- `result.sentences[]`: `sentence_id`, `syllables`, `articulation_rate`, `cv`(구하지 못하면 null), `rhythm_checked`, `detected_syllables`, `speech_s`, `passed`, `reason`(`fast` / `slow` / `uneven` / `no_speech`, 통과면 null)
- 문장 녹음은 판정 뒤 지운다(라운드 녹음은 올리지 않음).
